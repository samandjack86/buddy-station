# WorkBuddy 积分助手 · 操作手册

> 技能：`totorosir-workbuddy-score` ｜ 版本 3.1.7 ｜ 整理 zoulei
> 主线是**跟 WorkBuddy 说话**，不是敲命令。命令行在附录。

---

## 00 这东西是什么

一个技能包 + 一条每日定时任务，合起来自动干三件事：

- **技能**（手）：装在 WorkBuddy 里，负责读积分、签到、跑旅行。说「签到」它就动。
- **定时任务**（闹钟）：凌晨定点叫醒那个技能，不需要你在场、也不需要你发消息。

---

## 01 第一步 · 装 skill

**跟它说一句**（不用找按钮、不用进设置）：

> 帮我装一下 `totorosir-workbuddy-score` 这个 skill

或者：

> 搜一下 WorkBuddy 积分助手，帮我装上

**装到哪儿**：用户级目录，所有项目通用，换项目不用重装。

```
C:\Users\70547\.workbuddy\skills\totorosir-workbuddy-score\
```

落到这个位置就对了。**不需要重启客户端**，装完即生效。

**确认装好了**——随口问一句：

> 我的积分多少？

能报出余额、本周进度、活动剩余天数就说明活了。如果它反问「你想查哪儿的积分」，那就是没装上，回到开头再来一次。

> 触发词不用背。说「签到」「查积分」「派猫猫旅行」「还差几天满勤」，随便哪种说法它都认。

## 02 第二步 · 配定时任务

**一句话说全三件事：时间 + 干什么 + 不要什么。**

> 每天早上 2 点，帮我签到，然后把派猫猫旅行也跑完 —— 先领已到达的奖励，再派人出门。不用生成桌面报告，也不用推送通知。

这句话里其实有五个信息：

| 信息     | 对应的话               |
| -------- | ---------------------- |
| 时间     | 每天早上 2 点          |
| 做什么   | 签到 + 跑旅行闭环      |
| 顺序     | 先领奖励，再派人       |
| 不要什么 | 不生成报告、不推送     |
| 安全前提 | 签过就跳过，不重复发奖 |

**它会建一条每日重复任务**：自动化列表里能看到，每天 02:00，状态启用。

任务详情里会写一行执行动作。**那是给它自己看的，你不用管、也不用记**——凌晨没有你在场，那就是它唯一的「手」。

> **为什么必须有**：定时任务触发时没有对话、没人发消息，触发词无从命中，所以动作必须写死。这不是要你敲命令，是让它自己能干。

**确认在跑**：

> 我的定时签到任务在跑吗？最近一次什么结果？

它会翻执行记录告诉你：几点跑的、签到成功还是跳过、派到哪个地点、加了多少分。

> ⚠️ **一个坑**：凌晨 2 点电脑得开着。关机、睡眠、断网都不会跑。要是习惯晚上关电脑，把时间改成确定开机的点，比如「每天上午 10 点」。

## 03 第三步 · 验证一次

别等第二天，现在就让跑一次：

> 现在帮我跑一次签到和旅行，把结果报给我

结果只有三种：

| 它会说什么           | 含义                               |
| -------------------- | ---------------------------------- |
| 签到成功，+100 分    | 第一次签，正常                     |
| 今天已经签过了，跳过 | **也是正常**，不会重复发奖         |
| 报错 / 说没登录      | 看第 05 节，或直接说「先登录再试」 |

> 重复问、重复跑都没事。签到幂等，旅行奖励是「到了就等着，下次自动领」——不会丢分，也不会多得。

## 04 日常三句话

配好之后平时只用这三句，别的都不用记：

| 你说               | 它做什么                             |
| ------------------ | ------------------------------------ |
| 我的积分多少？     | 报余额、本周进度、活动还剩多少天     |
| 今天签到了吗？     | 查记录；没签会提醒你现在补一句就行   |
| 派猫猫旅行到哪了？ | 报当前地点、还有多久到、到了能领几分 |

偶尔会用到的两句：

| 你说                     | 它做什么                                 |
| ------------------------ | ---------------------------------------- |
| 帮我派去健身房           | 指定地点派遣（四个地点收益一样，纯口味） |
| 把每天签到改成上午 10 点 | 改定时任务时间，其他不变                 |

---

## 05 出问题怎么问

不用查命令、不用翻日志，描述现象就行：

| 遇到的情况            | 你就这么说                       |
| --------------------- | -------------------------------- |
| 不确定昨天跑没跑      | 昨天签到跑了吗？结果怎么样？     |
| 说连接失败 / 网络错误 | 重试一次                         |
| 说未登录 / token 过期 | 先登录 WorkBuddy，再跑一次       |
| 分好像没涨            | 查一下我这两天的签到记录         |
| 没收到系统通知        | 签到跑了吗？通知没弹但分到了就行 |
| 想让它别推送          | 以后不要推送到任何渠道           |
| 想换个时间跑          | 把签到任务改到晚上 11 点         |

> 它**不会编数据**。查不到就说查不到，接口报错就如实报错。真给了你一个数字，那一定是查到的。

## A1 底层命令

只有三种人需要这节：要手改自动化、要排查故障、要把这东西交给别人。日常请忽略。

```
C:\Users\70547\.workbuddy\binaries\python\versions\3.13.12\python.exe
C:\Users\70547\.workbuddy\skills\totorosir-workbuddy-score\scripts\buddy_station.py
```

> ⚠️ 脚本用手工参数解析，**没有 `--help`**。敲它不会出帮助，只会直接跑一次默认播报。

| 做              | 命令                                            |
| --------------- | ----------------------------------------------- |
| 只看积分        | `python buddy_station.py`                       |
| 签到            | `python buddy_station.py checkin`               |
| 签到 + 旅行闭环 | `python buddy_station.py checkin --travel-auto` |
| 只跑旅行闭环    | `python buddy_station.py --travel-auto`         |
| 指定派遣地点    | `--location 1~4`                                |
| 生成桌面报告    | `--html`                                        |
| 输出 JSON       | `--json`                                        |
| 关弹窗 / 关推送 | `--no-toast` / `--no-push`                      |

**派遣地点**（收益完全相同，不写 `--location` 就随机）

| 编号 | 地点     | 时长          | 积分         |
| ---- | -------- | ------------- | ------------ |
| 1    | 咖啡馆   | 随机 1–4 小时 | 随机 5–10 分 |
| 2    | 商场店铺 | 随机 1–4 小时 | 随机 5–10 分 |
| 3    | 健身房   | 随机 1–4 小时 | 随机 5–10 分 |
| 4    | 古镇客栈 | 随机 1–4 小时 | 随机 5–10 分 |

**报错对照**

| 报什么                       | 怎么回事                                                     |
| ---------------------------- | ------------------------------------------------------------ |
| `HTTP 0, getaddrinfo failed` | 本机 DNS / 网络瞬时抽风，**不是 token 问题**，重试一次通常就好 |
| `10001`                      | 今天已签到，正常幂等返回                                     |
| `HTTP 404`                   | 域名错，要用登录态里的 `auth.domain`；旅行接口路径不带 `/v2` |
| 500 / 空响应                 | 活动期后端切换偶发，脚本自带重试 3 次                        |
| 今日派遣已达上限             | 正常，服务端限次，次日恢复                                   |

## A2 换机器 · 授权通道

Windows 上装完就能用，因为能直接读本机登录态。**换到 Mac / Linux，或客户端长期不开**，才需要下面两条。

| 通道             | 场景                   | 做法                                                         |
| ---------------- | ---------------------- | ------------------------------------------------------------ |
| A · 本机登录态   | Windows，客户端已登录  | 零配置，直接跑                                               |
| B · 网页会话授权 | Mac / Linux 本地解不开 | `--snippet` 取码 → 同会话浏览器授权 → `--setup-code <授权码>` |
| C · 长效令牌     | 客户端长期关闭也要跑   | `--export-rt` 导出 → `--setup-rt <token>` 落盘               |

**先问该走哪条**：

> 帮我探测一下积分助手的授权通道，看推荐哪条

它会在后台跑 `--probe`，回你一段 JSON 里有推荐通道。

凭据位置：通道 B `~/.workbuddy/checkin-cred.json`、通道 C `~/.workbuddy/checkin-rt.json`，权限 0600。

> 这几步也可以**整段丢给它做**，你只需要在浏览器里点一次授权。真要动手的只有「打开授权页登录」这一下。

## A3 安全边界

**只碰三个写接口**

| 操作     | 接口                                           |
| -------- | ---------------------------------------------- |
| 签到     | `POST /v2/billing/meter/daily-checkin`（幂等） |
| 旅行领取 | `POST /activity/growth/buddy/travel/claim`     |
| 旅行派遣 | `POST /activity/growth/buddy/travel/depart`    |

**明确不会做**

- 不调用兑换、抽奖等任何其他写接口
- 不加 `--travel-auto` 时，旅行部分纯只读，不会派人
- 派出前必查今日上限，达上限不发写请求，不会超发
- 不打印、不外传、不修改登录态 token
- 除写桌面报告和弹系统通知，不改任何文件
- 查不到的数据如实说「暂不支持」，不编造——积分流水、兑换条件至今没有只读接口

**什么时候会停下来**

| 情况                    | 行为                             |
| ----------------------- | -------------------------------- |
| 登录态缺失 / token 过期 | 停止，提示「请先登录 WorkBuddy」 |
| 接口返回非 0 / 非 200   | 停止并如实报告，不猜结果         |
