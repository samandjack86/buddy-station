这东西是什么

一个技能包加一条每日定时任务，合起来自动帮你干三件事。你全程只需要说人话。

技能
积分助手
装在 WorkBuddy 里，负责读积分、签到、跑旅行。说「签到」它就动。
定时任务
每天自动跑
凌晨定点叫醒上面那个技能，不需要你在场，也不需要你发消息。
分工技能是「手」，定时任务是「闹钟」。手装一次一直在，闹钟负责每天叫它起来干活。
01

第一步 · 装 skill

01
跟它说一句
不用找按钮，不用进设置，直接在对话框里说。
直接说
帮我装一下 totorosir-workbuddy-score 这个 skill
或者这么说
搜一下 WorkBuddy 积分助手，帮我装上

它会自己搜、自己装，装完告诉你装在哪、能不能用。

02
装到哪儿了
用户级目录，所有项目都能用，换项目不用重装。
C:\Users\70547\.workbuddy\skills\totorosir-workbuddy-score\

落到这个位置就对了。不需要重启客户端，装完即生效。

03
确认装好了
不用看日志，随口问一句就知道。
直接说
我的积分多少？

能报出余额、本周进度、活动剩余天数，说明技能活了。如果它反问「你是想查哪儿的积分」，那就是没装上，回 01 再来一次。

不用记触发词不用背。说「签到」「查积分」「派猫猫旅行」「还差几天满勤」，随便哪种说法它都认。
02

第二步 · 配定时任务

01
还是一句话
把「时间 + 干什么 + 不要什么」说全，一次到位，省得它反问。
直接说
每天早上 2 点，帮我签到，然后把派猫猫旅行也跑完 —— 先领已到达的奖励，再派人出门。
不用生成桌面报告，也不用推送通知。

这一句里其实塞了五个信息：

信息对应的话
时间每天早上 2 点
做什么签到 + 跑旅行闭环
顺序先领奖励，再派人
不要什么不生成报告、不推送
安全前提签过就跳过，不重复发奖
02
它会建一条每日重复任务
在自动化列表里能看到：每天 02:00，状态启用。

任务详情里会写一行执行动作。那是给它自己看的，你不用管、也不用记 —— 凌晨没有你在场，那就是它唯一的「手」。

为什么必须有定时任务触发时没有对话、没人发消息，触发词无从命中，所以动作必须写死。这不是要你敲命令，是让它自己能干。
03
确认它在跑
直接说
我的定时签到任务在跑吗？最近一次什么结果？

它会翻执行记录告诉你：几点跑的、签到成功还是跳过、派到哪个地点、加了多少分。

一个坑凌晨 2 点电脑得开着。关机、睡眠、断网都不会跑。要是你习惯晚上关电脑，把时间改成确定开机的点，比如「每天上午 10 点」。
03

第三步 · 验证一次

别等第二天早上才看，现在就让跑一次，当场看结果。

直接说
现在帮我跑一次签到和旅行，把结果报给我

结果只有三种，对号入座：

它会说什么含义
签到成功，+100 分第一次签，正常
今天已经签过了，跳过也是正常，不会重复发奖
报错 / 说没登录看第 05 节，或直接说「先登录再试」
放心重复问、重复跑都没事。签到幂等，旅行奖励是「到了就等着，下次自动领」——不会丢分，也不会多得。
04

日常三句话

配好之后，平时只会用到这三句。别的都不用记。

你说它做什么
我的积分多少？报余额、本周进度、活动还剩多少天
今天签到了吗？查记录；没签会提醒你现在补一句就行
派猫猫旅行到哪了？报当前地点、还有多久到、到了能领几分

偶尔会用到的两句

你说它做什么
帮我派去健身房指定地点派遣（四个地点收益一样，纯口味）
把每天签到改成上午 10 点改定时任务时间，其他不变
05

出问题怎么问

不用查命令、不用翻日志。描述现象就行，它自己去查。

遇到的情况你就这么说
不确定昨天跑没跑昨天签到跑了吗？结果怎么样？
说连接失败 / 网络错误重试一次
说未登录 / token 过期先登录 WorkBuddy，再跑一次
分好像没涨查一下我这两天的签到记录
没收到系统通知签到跑了吗？通知没弹但分到了就行
想让它别推送以后不要推送到任何渠道
想换个时间跑把签到任务改到晚上 11 点
原则它不会编数据。查不到就说查不到，接口报错就如实报错。真给了你一个数字，那一定是查到的。

A2

换机器 · 授权通道

附录

Windows 上装完就能用，因为能直接读本机登录态。换到 Mac / Linux，或客户端长期不开，才需要走下面两条。

通道 A
本机登录态
Windows，客户端已登录。零配置。
通道 B
网页会话授权
Mac / Linux 本地解不开时用，一次性授权。
通道 C
长效令牌
让脚本在客户端长期关闭时也能跑。

先问该走哪条

直接说
帮我探测一下积分助手的授权通道，看推荐哪条

它会在后台跑 --probe，回你一段 JSON，里面有推荐通道。

通道 B · 一次性网页授权

  1. 让它跑 --snippet，拿到 WBAUTH1: 开头的授权码
  2. 在同一个浏览器会话里打开授权页完成登录
  3. 让它跑 --setup-code <授权码> 落盘

凭据存到 ~/.workbuddy/checkin-cred.json，权限 0600，只有你能读。

通道 C · 长效令牌

  1. 让它跑 --export-rt 导出 refresh_token
  2. 让它跑 --setup-rt <token> 落盘

此后每次运行自动用令牌换新 accessToken 并回写，客户端不开也能签到。凭据在 ~/.workbuddy/checkin-rt.json。

省事这几步也可以整段丢给它做，你只需要在浏览器里点一次授权。真要动手的只有「打开授权页登录」这一下。
A3

安全边界

附录

知道它不会干什么，比知道它能干什么更重要。

只碰三个写接口

操作接口
签到POST /v2/billing/meter/daily-checkin（幂等）
旅行领取POST /activity/growth/buddy/travel/claim
旅行派遣POST /activity/growth/buddy/travel/depart

明确不会做

  • 不调用兑换、抽奖等任何其他写接口
  • 不加 --travel-auto 时，旅行部分纯只读，不会派人
  • 派出前必查今日上限，达上限不发写请求，不会超发
  • 不打印、不外传、不修改登录态 token
  • 除写桌面报告和弹系统通知，不改任何文件
  • 查不到的数据如实说「暂不支持」，不编造 —— 积分流水、兑换条件至今没有只读接口

什么时候会停下来

情况行为
登录态缺失 / token 过期停止，提示「请先登录 WorkBuddy」
接口返回非 0 / 非 200停止并如实报告，不猜结果
